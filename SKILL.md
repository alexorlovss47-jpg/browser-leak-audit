# Аудит утечек браузера при VPN

Проверка браузера на сетевые утечки и fingerprinting, когда трафик идёт через VPN-сервер. Скилл построен по разбору habr.com/ru/articles/1111276 (обзор утечек, ноябрь 2026).

## When to Use

- «Проверь утечки», «прогони browserleaks», скриншоты тестов
- После смены VPN-сервера/ссылок — убедиться, что клиент чистый
- Подозрение, что сервис банит по отпечатку

## Принцип (из статьи)

VPN меняет только сетевой путь (IP). Браузер продолжает светить часовой пояс, язык, WebRTC, DNS, Canvas/WebGL. 6 типов утечек:

1. **IP** — трафик вышел не тем интерфейсом
2. **DNS** — запрос имени мимо VPN (системный DNS, DoH браузера, кэш)
3. **WebRTC** — собственные сетевые механизмы браузера
4. **IPv6** — VPN накрыл только IPv4
5. **Несоответствие окружения** — язык/часовой пояс ≠ гео IP
6. **Fingerprinting** — отпечаток узнаёт между визитами

Ключевое: **несовпадение ≠ утечка**. Русский язык при NL IP — нормально (путешественник, эмигрант). Два разных подхода: *согласование* (подогнать браузер под гео VPN) и *стандартизация* (сделать всех одинаковыми, Mullvad Browser). Для одного личного сервера гоняться за гео-совпадением не нужно.

## Тесты (открывать в браузере пользователя)

| Тест | Что смотрим | Хорошо | Плохо |
|---|---|---|---|
| `browserleaks.com/webrtc` | публичный IP, локальный IP | IP = IP сервера, локальный = 127.0.0.1/mDNS | Засветил реальный IP провайдера |
| `test-ipv6.com` | IPv6-адрес, оценка | v6 отсутствует (0/10) = дыры нет | Есть IPv6, а VPN его не накрывает |
| `browserleaks.com/dns` | список DNS-серверов | один провайдер, одна локация | Много провайдеров/локаций = утечка |
| `ipleak.net` | IP, WebRTC, DNS, fallback | всё на IP сервера | Локальный IP, чужие резолверы |
| `browserleaks.com/canvas` | уникальность отпечатка | — | 100% уникальность = узнаваем (не утечка) |

**Скриншоты пользователя читать через OCR** (не vision — тот падает):

## Диагностика на маке

```bash
scutil --dns | grep nameserver        # системный DNS
ifconfig | grep inet6                 # глобальный IPv6 (fe80/::1 не считать)
sudo -n true                          # есть ли passwordless sudo
```

## Фикс Chrome: закрепить Cloudflare DoH

Признак проблемы: `browserleaks.com/dns` показывает **Cloudflare + Google** (паттерн Secure DNS с автоподбором) или российские резолверы при включённом VPN.

1. `chrome://settings/security`
2. «Использовать безопасный DNS-сервер» → **«Выбрать поставщика услуг DNS»**
3. В поле: `https://cloudflare-dns.com/dns-query`
4. **Полностью перезапустить Chrome** (не только вкладку)
5. Перепроверить тест: должно стать **только Cloudflare**, Google исчезнуть

Управляемая политика Chrome (plist в /Library/Managed Preferences, ключи DnsOverHttpsMode и DnsOverHttpsTemplates) требует root — на macOS-машине sudo с паролем, поэтому ставим ручками через UI.

**Почему Cloudflare не страшен при блокировках в РФ:** DoH идёт через туннель, наружу выходит уже с NL-сервера — РФ-блокировки на путь не действуют. При упавшем VPN просто не резолвится (fail-closed), Chrome фолбэчит на системный DNS.

## Чего НЕ делать

- **Не ставить кучу антифингерпринтинговых расширений** — Chameleon + CanvasBlocker + подмена UA дерутся за одни параметры и делают отпечаток *уникальнее*. «Количество изменённых параметров — плохая мера защиты»
- Не гоняться за гео-совпадением всех признаков при одном личном сервере
- Не включать WebRTC-блокировку вслепую — ломает видеозвонки; нужен только `webRTCIPHandlingPolicy=disable_non_proxied_udp`
- Не выключать Secure DNS в пользу системного роутера — системный DNS локального провайдера, это хуже

## Результаты аудита 24.11.2026 (Chrome, мак user)

Сетевая часть **чистая, чинить нечего**:
- ✅ IP — <SERVER_IP> (NL), всё через туннель
- ✅ WebRTC — «Нет протечек», локальный 127.0.0.1, mDNS прячет
- ✅ IPv6 — 0/10, v6 не работает = дыры нет
- ✅ DNS — после фикса: 11 серверов, 1 провайдер (Cloudflare), 1 локация (Франкфурт)
- ⚠️ Canvas — 100% уникальность `<canvas-hash>` — узнаваемость, не утечка. Цена обычного Chrome, для личных задач не критично
- Системный DNS мака: <ROUTER_DNS> (домашний роутер) — не используется браузером после фикса

**Mullvad Browser не обязателен.** Ставить только если понадобится неузнаваемость (антидетект-сценарии) — как второй браузер, не заменяя Chrome.

## Ограничения метода

Тест DNS показывает, **какие** резолверы ответили, но не доказывает **путь** запроса. Косвенно путь подтверждается чистым IP/WebRTC. Если нужна точность — смотреть, не светятся ли российские резолверы при включённом VPN.
